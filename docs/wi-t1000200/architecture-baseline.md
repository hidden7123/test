# 系统设计

## 1. 整体方案与设计基线

- 需求基线引用：本设计唯一依据为已批准的需求基线 `docs/wi-t1000200/requirements.md`（v1，初始构建）。该基线状态为 blocked：业务任务仅含标识“1”，无产品语义——无产品目标、服务对象、场景、数据对象、约束或验收条件（需求第 2、11 节）。
- 应用类型路由：按设计分类契约路由为 fullstack-complex（歧义默认）。该路由仅决定设计流程形态，不构成产品事实：批准快照中既无“只需浏览器页面/静态/本地状态且明确无服务端”的声明，也无任何服务端、权威数据库、认证、后台任务、外部服务或跨用户/设备同步的需求证据，两侧均无法排除。
- 设计结论：blocked（核心边界无法安全确定）。应用形态（纯前端 / 前后端单体 / 其他）、核心数据归属、权限模型与运行方式在零业务内容下均无法安全冻结；冻结任一具体技术栈、模块或接口都会虚构产品范围，与批准需求明确记录的“业务内容缺失”相悖。
- 未冻结事项及依据：
  - 整体技术栈：不冻结。新建纯前端应用默认 React/Vite SPA、需服务端的新建单体 Web 应用默认 Hono + React/Vite，但当前无任何证据判定应用属于哪种形态，采用任一默认即虚构系统边界；已有项目继承路径亦不适用——工作区根目录已核验为初始空仓库（仅 README“# test”，无 package.json，无 app/、src/、client/、server/ 目录）。
  - 公共模块复用：不选择任何 CommonApp 模块（含 dbkit）。无服务端权威数据、跨用户/设备共享、结构化查询/事务、认证或审计的需求或证据，按“无需求或证据不新增基础设施与公共包”原则，不查询模块目录，不产生 `commonapp install` 标记，不引入服务端框架或数据库层。
  - 工作区初始化：不执行。所选模块及依赖闭包不含 dbkit，按规则不生成 `workspace-bootstrap.json`、不调用初始化器、不要求 `platform-baseline.json`。
  - UI 呈现基线：不输出。需求未声明任何用户界面、用户旅程或设备适配要求（需求第 4、6、7 节）。
  - 技术契约：不生成。不存在需要前后端共同遵守并交接的 API 契约（无任何已声明能力）。
  - 运行与可靠性：不输出。无可运行应用定义，最小运行契约（启动命令、端口、持久化路径）无承载对象。
- 高影响开放项（唯一，与需求基线第 11 节一致）：业务任务“1”的业务内容缺失。解除方式：用户补充业务任务内容（目标、场景、期望结果、约束任意一项即可）→ 需求基线升版 v2 并自 AC-01 起补齐验收条件 → 本设计按新基线重新分类并冻结整体方案、模块边界与接口。
- 边界保持：本文件不改写需求基线的产品语义与 blocked 判定。设计 blocked 不阻塞本阶段契约动作：architecture-baseline.md 已按阶段契约留档；实现与验证阶段在本开放项解除前不具备可实施输入，该事实如实记录，不视为本设计的交付缺陷。

## 2. 领域责任、模块边界与接口摘要

- 领域责任与数据归属：无可冻结项。批准需求未声明任何业务对象、生命周期状态或业务规则（需求第 4-6 节），核心事实的唯一归属无从确定；为避免虚构，不为任何“可能的”对象指定 owner。
- 模块边界：无可定义的内部模块或边界。任何模块划分都等于虚构 MVP 范围；公共模块选择结论见第 1 节（零选择，依据不足）。
- 接口摘要：无接口、无固定调用方向可声明；不存在对外能力接口或外部服务边界。
- 上述空白均为需求基线已记录阻塞项（业务内容缺失）的直接推导结果，非设计遗漏；解除阻塞并升版需求后，本节按实际业务对象补齐各模块职责、数据归属与接口摘要。
