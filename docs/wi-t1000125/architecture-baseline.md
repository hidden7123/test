## 1. 整体方案与设计基线

### 架构结论

**结论：新建纯前端单页应用（React + Vite），任务数据以浏览器 localStorage 持久化；不引入服务端、数据库、外部集成与任何公共模块。**

依据（来自已批准需求基线的事实）：

- 使用者为单一"通用使用者"，无角色体系、无认证、无多人协作与任务分配；
- 持久化要求仅为"页面刷新或重新打开后仍可读取"，属于单设备/单浏览器内的存续，无跨用户、跨设备共享；
- 无通知提醒、后台处理和外部服务集成；未提出性能、审计、国际化、部署等约束。

按设计规则，仅单浏览器数据、无服务端业务的应用采用 React/Vite SPA，不保留服务端框架，也不查询 CommonApp 模块目录——本项目属于该类，故本次未执行任何 CommonApp catalog 查询。

**边界后果（对用户的直接影响）：**

- 任务数据只存在于当前浏览器：更换浏览器或设备后数据不可见；清除该站点的浏览器数据会永久丢失全部任务且不可恢复（与需求的硬删除规则一致）；
- 若后续需求升级为跨设备同步或多人协作，"数据唯一归属＝本机浏览器"的结论必须重新打开并引入服务端方案。

### 技术栈与最小运行契约

| 项 | 冻结值 |
| --- | --- |
| 前端框架 | React + Vite（单页应用） |
| 样式实现 | Tailwind CSS（承载第 3 节 Modern SaaS 视觉 Token） |
| 包管理器 | npm |
| 持久化 | 浏览器 localStorage，单键 `virtual-tasks` |

- startCommand: npm run dev
- 构建命令：`npm run build`（产出静态资源，可由任意静态服务器承载；本设计不做部署声明）
- 端口：开发期使用 Vite 默认端口 5173（可经 Vite 配置调整）；应用无服务端监听，`PORT` 与 `DB_PATH` 等参数不适用
- 无数据库、无迁移；数据位置由浏览器管理，不存在文件路径

### 公共模块复用

无复用。纯 localStorage 应用按规则不查询 CommonApp catalog；工作区内也无既有代码可复用。创建、列表、状态规则、编辑、删除等能力全部在项目内实现，不新增公共包（用户未提出公共模块演进要求）。

### 开放项（非阻塞）

需求中标注"推荐基线"的功能与规则（状态转换矩阵、硬删除、持久化范围、桌面 Web 等）尚待用户在后续阶段确认；本设计按其现状冻结技术落点。其中"持久化仅限本浏览器"若被调整为跨设备，将触发整体方案重开。

## 2. 领域责任、模块边界与接口摘要

系统仅两个内部模块，调用方向固定、反向不存在：

```text
task-ui（界面模块）→ task-store（任务数据与规则模块）→ localStorage
```

建议落位：task-store → `src/domain/`，task-ui → `src/` 界面组件。

### task-store：任务数据与规则模块

- **职责与数据归属**：虚拟任务记录的唯一归属方；负责 localStorage 读写与序列化、名称非空校验、状态转换合法性判定（允许：待处理→进行中、待处理→已完成、进行中→已完成、进行中→待处理；已完成不可再迁移；删除为记录移除而非状态值）。业务判定不外放。
- **记录结构（冻结字段命名）**：`id`（字符串，创建时用 `crypto.randomUUID()` 生成）、`name`（去除首尾空白后非空的字符串）、`description`（可空字符串，默认空串）、`status`（枚举 `todo | in_progress | done`）、`createdAt`（ISO 8601 时间字符串，创建时写入后不变）。中文状态标签（待处理/进行中/已完成）由界面层映射，本模块只产出枚举值，保证系统不出现状态模型之外的值。
- **存储约定**：全部未删除记录以 JSON 数组存于 localStorage 单键 `virtual-tasks`，本模块是唯一读写方。键不存在按空列表处理；内容解析失败时返回错误供界面进入错误态，不自动清写已存内容（仅用户后续成功创建任务时才覆盖写入）。
- **接口摘要**（模块导出函数；纯前端内部调用而非 HTTP 契约，故不生成技术契约文件）：
  - `createTask({ name, description })` → 新记录；名称非法时返回校验错误；
  - `listTasks()` → 全部未删除记录；
  - `transitionTask(id, targetStatus)` → 更新后的记录；非法转换返回错误并保持原状态；
  - `updateTask(id, { name, description })` → 更新后的记录；名称同样受非空校验；
  - `deleteTask(id)` → 硬删除记录，无软删除/回收站。

### task-ui：界面模块

- **职责**：应用壳、任务列表与详情展示、创建/编辑表单、状态操作入口、删除确认，以及空/错误/成功反馈。不含业务判定——名称校验、转换合法性、删除语义全部调用 task-store，界面只把返回错误转为可读提示。
- **操作入口与状态联动**：按当前 `status` 渲染可用迁移入口（`done` 任务不出现"开始/完成"入口）；即使入口被绕过调用，task-store 仍拒绝非法转换，两层共同保证"已完成不可迁移、状态保持不变"。
- **删除确认**：由界面承担（确认对话）；取消则不调用 `deleteTask`，任务保持不变。

## 3. UI 基线

- **展示模板 ID：`split-master-detail`**（实现阶段按此 ID 消费模板资源）。依据：核心动作是逐条处理任务记录（创建、开始、完成、退回、编辑、删除），任务列表与选中任务详情/操作需要协同呈现，属于列表+详情工作流。
- **视觉风格：Modern SaaS**（通用业务应用默认方向；此为视觉方向名称，非实现资源 ID）。Token 方向：柔和中性色表面、细分隔线、少阴影、中等圆角、清晰字重层级；一个主色承担主要动作；状态色仅映射 `todo / in_progress / done` 三态标签；动效仅做短促操作反馈。
- **应用壳与主工作区**：单页应用壳，无多级导航。顶部上下文栏含应用名"虚拟任务"与"新建任务"入口；主工作区左右分区：左侧任务列表（名称、状态标签、创建时间），右侧当前选中任务的详情与操作（开始/完成/退回、编辑、删除）。新建入口展开创建表单（名称必填、描述可选），校验错误就地提示。
- **目标设备**：桌面 Web。不设计、不验收窄屏/移动端（需求明确列为范围外）；验收使用默认桌面视口，不强制固定尺寸。
- **全局状态**：
  - 空数据：列表为空时展示引导创建的空态；
  - 错误：名称必填提示、非法状态转换提示、localStorage 读取失败的错误态；删除确认取消不算错误；
  - 成功：创建/迁移/编辑/删除后列表与详情即时更新（本地同步操作，即时反馈）；
  - 加载态与无权限态不适用（无异步读取；无角色体系）。
