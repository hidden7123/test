## 1. 项目背景与目标

### 背景

当前工作区是一个测试项目，已包含一个 Git 仓库。用户需要测试 Git 是否能正常工作——即验证 Git 仓库的初始化、远程绑定、分支管理和提交功能是否处于可用状态。

### 当前状态（已核实）

经实际检查，当前项目 Git 状态如下：

| 检查项 | 结果 |
|--------|------|
| Git 仓库是否已初始化 | ✅ 是（`.git` 目录存在） |
| 远程仓库是否已绑定 | ✅ 是（origin → `https://github.com/hidden7123/test.git`） |
| 当前分支 | ⚠️ HEAD 处于 detached 状态（位于 commit `1865d30`） |
| 提交历史 | 1 次提交（`1865d30 Initial commit`） |
| 未提交变更 | `.gitignore` 已修改（新增 `.expert-team/` 排除规则），未暂存；`docs/` 目录未跟踪 |
| 本地分支 | 无（HEAD detached，无任何本地分支） |

### 目标

1. **验证 Git 仓库可用性**：确认 Git 仓库已初始化、远程已绑定，基本版本控制功能正常。
2. **测试 Git 核心功能**：验证 `git status`、`git remote`、`git branch`、`git log`、`git add`、`git commit` 等核心命令正常工作。
3. **修复 Git 状态异常**：处理 HEAD detached 状态和未提交的变更，使仓库进入正常可工作状态，验证修复操作有效。

## 3. 用户旅程与关键场景

### 场景 A：查看 Git 绑定状态

1. 开发者执行 Git 状态检查命令（`git status`、`git remote -v`、`git log`、`git branch`）。
2. 系统返回当前仓库状态：已初始化、已绑定远程、HEAD detached、存在未提交变更。
3. 开发者确认项目**已经绑定了 Git**。

### 场景 B：修复 HEAD Detached 状态

1. 开发者发现 HEAD 处于 detached 状态，无本地分支。
2. 开发者基于当前 commit 创建本地分支（如 `main`）。
3. HEAD 从 detached 切换到新分支，进入正常工作状态。

### 场景 C：处理未提交的 .gitignore 变更

1. 开发者检查 `.gitignore` 的修改内容（新增 `.expert-team/` 排除规则）。
2. 开发者将变更暂存并提交到当前分支。
3. 工作区变为 clean 状态。

### 场景 D：项目未绑定 Git 时的初始化（当前不适用，但作为备选场景保留）

1. 如果项目尚未初始化 Git，执行 `git init`。
2. 添加远程仓库地址：`git remote add origin <url>`。
3. 创建初始提交并推送到远程。

> **注意**：经检查，当前项目**已经绑定 Git**，场景 D 不需要执行。

## 4. 核心实体与术语

| 术语 | 含义 |
|------|------|
| Git 仓库 | 通过 `git init` 创建的版本控制仓库，包含 `.git` 目录 |
| 远程仓库（Remote） | 托管在服务器上的 Git 仓库，通过 `origin` 别名引用 |
| HEAD Detached | HEAD 指向具体 commit 而非分支引用的状态，提交不会归属到任何分支 |
| .gitignore | 指定 Git 应忽略的文件和目录的配置文件 |
| 暂存区（Staging Area） | `git add` 后、`git commit` 前的变更暂存区域 |

## 5. 状态模型与业务规则

### Git 仓库状态模型

```
[未初始化] --git init--> [已初始化/无远程] --git remote add--> [已初始化/已绑定远程]
                                                              |
                                                              v
                                                    [正常工作状态] <--创建分支/提交变更-- [HEAD Detached/有未提交变更]
```

### 业务规则

- **BR-01**: 项目已有 `.git` 目录时，不应重复执行 `git init`，避免破坏现有仓库。
- **BR-02**: 项目已有远程绑定时，不应重复添加同名 remote（`origin`），如需更换应使用 `git remote set-url`。
- **BR-03**: HEAD 处于 detached 状态时，应创建本地分支使 HEAD 指向分支引用，确保后续提交归属到分支。
- **BR-04**: 提交变更前应确认 `.gitignore` 修改内容合理且符合预期。
- **BR-05**: 推送到远程前应确认远程仓库可访问且有推送权限。

## 6. 分模块功能需求

### 模块 1：Git 状态检查

- **F-01**: 检查 Git 仓库是否已初始化（`.git` 目录是否存在）。
- **F-02**: 检查远程仓库绑定状态（`git remote -v` 输出）。
- **F-03**: 检查当前分支和 HEAD 状态（`git branch`、`git status`）。
- **F-04**: 检查提交历史（`git log`）。
- **F-05**: 检查未提交的变更（`git status`、`git diff`）。

### 模块 2：Git 状态修复

- **F-06**: 创建本地分支以解决 HEAD detached 状态（`git checkout -b main` 或 `git branch main && git checkout main`）。
- **F-07**: 暂存并提交 `.gitignore` 变更（`git add .gitignore && git commit -m "更新 .gitignore"`）。
- **F-08**: （可选）将提交推送到远程仓库（`git push origin main`）。

### 模块 3：Git 初始化（仅在未绑定时执行）

- **F-09**: 执行 `git init` 初始化新仓库（当前不适用）。
- **F-10**: 添加远程仓库地址 `git remote add origin <url>`（当前不适用）。
- **F-11**: 创建初始提交并推送到远程（当前不适用）。
