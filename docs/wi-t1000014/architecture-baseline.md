# 系统设计

<!-- system-design: scope -->
## 1. 整体方案与设计基线

**架构结论**：纯前端单页应用，浏览器本地存储承载全部业务数据。无服务端、无数据库、无认证、无外部集成。

**需求基线引用**：本设计依据已批准的需求基线 `docs/15778188013600768/requirements.md`（sha256:3eeb0ef7272b048789a9dbaeaef28594e20c0c50f679cf45bfe8a7e28a56ef44，「业务任务登记与跟踪 功能需求说明」v1）。产品语义、状态模型与验收语义以该基线为准，本设计只确定其技术承载，不改变产品语义。

**技术选型与依据**：

| 决策点 | 结论 | 依据 |
| --- | --- | --- |
| 系统形态 | React + Vite 单页应用（SPA） | 新建纯前端应用的默认组合；需求为单端桌面 Web，无服务端能力诉求 |
| 数据与状态 | 浏览器 localStorage 持久化 | 需求持久性的可观察结果为「页面刷新或重新打开后仍可读取」；无跨用户/跨设备共享 |
| 服务端/数据库 | 不引入 | 无权威数据共享、认证、后台任务、外部集成诉求；引入即无证据的过度设计 |
| 公共模块 | 不引入（不查询 CommonApp） | 纯 localStorage 应用按规则不查询 CommonApp catalog |

**实现入口与运行契约**：

- `startCommand: npm run dev`（Vite 开发服务器，浏览器验证使用同一前端入口）
- 构建交付：`npm run build` 产出纯静态文件，可由任意静态服务承载，无服务端进程
- 无数据库与端口参数约定（`DB_PATH`/`PORT` 等服务端约定不适用）；无服务端健康检查
- 页面/交互边界（桌面 Web 单页，两个视图）：
  - **清单页**：任务列表（标题、当前状态、最近更新时间，默认按最近更新时间由近到远）、新建任务入口、按状态筛选；无任务时展示空态提示
  - **任务详情/编辑**：标题与说明的编辑保存、按当前状态提供的状态操作入口（「待处理」提供开始处理与取消，「进行中」提供完成与取消，终态不提供任何状态操作入口）、变更记录区域（原状态、新状态、发生时间，由近到远排列）
- 全局反馈：操作成功给出可感知反馈并显示最新状态；被拒绝的操作给出面向业务人员的可读中文提示，不改变当前状态、不新增变更记录，用户可继续执行当前状态允许的其他操作

## 2. 领域责任、模块边界与接口摘要

**核心事实唯一归属**：业务任务（标题、说明、当前状态、创建时间、最近更新时间）与变更记录（原状态、新状态、发生时间）唯一归属浏览器 localStorage 中的一个版本化本地数据集；内存中的任务列表是它的运行时投影，一切写入经由本地存储模块完成，页面刷新或重新打开后从同一数据集读回。

**内部模块与接口摘要**：

| 模块 | 职责 | 数据归属 | 接口摘要（调用方向） |
| --- | --- | --- | --- |
| 本地存储模块 | localStorage 读写与启动读回；读写异常（存储不可用、配额超限）转为可读错误反馈 | 任务与变更记录的唯一 owner | 向状态服务与页面组件提供任务、变更记录的读/写/追加接口；页面组件不直接访问 localStorage |
| 状态服务模块 | 状态机规则的唯一执行点：按需求基线转换表执行合法转换，拒绝非法转换（终态再变更、跳级、回退）并返回拒绝原因；重复触发同一操作只生效一次 | 无独立数据，操作结果写入本地存储模块 | 接受「当前状态 + 动作」，返回新状态或拒绝原因；成功转换时同步追加一条变更记录 |
| 页面组件层 | 清单页与详情/编辑视图的渲染和交互；状态操作入口的可见性由当前状态决定；标题保存前完成非空与长度校验，被拒绝时保留已填写内容并提示 | 无独立数据 | 通过状态服务发起状态操作，通过本地存储模块读写任务与变更记录 |

**调用方向**：

```text
页面组件 → 状态服务 → 本地存储模块 → localStorage
```

状态服务是唯一的状态变更判定点，页面组件不得绕过状态服务直接改写任务状态。无对外能力接口、无外部服务接入实现、无其他内部 Service。

**权限与数据可见性**：不设角色与权限体系（需求未提出）；数据仅在本浏览器内可见，无跨用户数据可见范围控制诉求。
