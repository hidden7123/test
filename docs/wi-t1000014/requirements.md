## 2. 用户旅程与关键场景

### J1 登记一项业务任务并推进到完成

1. 用户在清单页新建一项业务任务，系统将其置为「待处理」（见 M1）。
2. 用户开始处理该任务，状态由「待处理」变为「进行中」。
3. 用户完成该任务，状态由「进行中」变为「已完成」。
4. 关键决策点：每一步推进前，用户需要能确认当前状态与下一步可执行的动作。
5. 系统反馈：推进成功后界面上的状态与可执行动作同步更新，并新增一条变更记录。

### J2 更新任务内容

1. 用户打开一项已登记的任务。
2. 用户修改标题或说明并保存。
3. 系统反馈：清单与详情显示修改后的内容，最近更新时间随之更新。

### J3 取消任务

1. 用户打开一项「待处理」或「进行中」的任务。
2. 用户执行取消。
3. 系统反馈：状态变为「已取消」；「已取消」为终态，页面不再提供任何状态操作入口。

### J4 查看任务清单与变更记录

1. 用户打开清单页，看到每项任务的标题、当前状态和最近更新时间。
2. 用户打开某一项任务的详情，查看其变更记录区域。
3. 系统反馈：记录按发生时间由近到远展示原状态、新状态和发生时间；记录只增不改。

### J5 非法操作被拒绝

1. 用户打开一项「已完成」或「已取消」的任务。
2. 用户尝试再次改变其状态。
3. 系统反馈：页面不提供状态操作入口；若仍发起该操作，系统拒绝执行并给出可读提示，任务状态保持原样。

## 3. 状态模型与业务规则

### 3.1 状态定义

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| 待处理 | 已登记，尚未开始处理 | 否 |
| 进行中 | 已开始处理，尚未完成 | 否 |
| 已完成 | 处理完毕 | 是 |
| 已取消 | 用户主动取消 | 是 |

### 3.2 状态转换

| 序号 | 原状态 | 目标状态 | 触发动作 |
| --- | --- | --- | --- |
| T1 | 待处理 | 进行中 | 开始处理 |
| T2 | 进行中 | 已完成 | 完成 |
| T3 | 待处理 | 已取消 | 取消 |
| T4 | 进行中 | 已取消 | 取消 |

未被上表列出的状态组合一律视为非法转换，包括但不限于：跳过中间状态（如「待处理」直接到「已完成」）、回退到更早状态、终态再次变更。

### 3.3 通用约束

- 任一时刻一项任务只有一个当前状态；状态变化只发生在上表列出的转换中。
- 「已完成」与「已取消」为终态，不能从终态转到任何其他状态。
- 每次成功的状态变化追加一条变更记录，内容包含原状态、新状态和发生时间；记录不可修改、不可删除。
- 被拒绝的操作不改变当前状态，也不写入变更记录。
- 任务保存时标题不可为空；标题为空时拒绝保存并给出可读提示。
- 用户未提出角色与权限要求，本文件不定义角色、权限矩阵或数据可见范围。

## 4. 分模块功能需求

### M1 业务任务登记与编辑

- 新增任务：用户填写标题（必填）与说明（选填）后保存，系统将其置为「待处理」，并记录创建时间。
- 编辑任务：用户可修改标题与说明并保存，保存成功后最近更新时间更新。
- 边界与异常：
  - 标题为空或仅含空白字符时：拒绝保存，保留用户已填写内容并给出可读提示。
  - 标题超长时：拒绝保存并提示可接受的标题长度范围。
  - 保存过程中重复点击保存：只产生一条任务记录。

### M2 业务任务清单

- 清单展示每项任务的标题、当前状态和最近更新时间。
- 清单默认按最近更新时间由近到远排列。
- 清单中的状态与详情页展示的状态在任何时刻保持一致。
- 不存在任何任务时，清单显示空态提示，不展示占位任务。
- 用户可按状态筛选清单（推荐基线，可替换）。

### M3 状态推进与取消

- 详情页按 J1、J3 提供状态操作入口：开始处理、完成、取消。
- 可见入口由当前状态决定：「待处理」提供「开始处理」「取消」；「进行中」提供「完成」「取消」；终态不提供任何状态操作入口。
- 执行成功后，界面立即反映新状态，并同步更新可执行的入口；清单中该项任务的状态同步更新。
- 边界与异常：
  - 对终态任务发起状态操作：拒绝执行，保持原状态，给出可读提示（见 M4）。
  - 重复触发同一操作：只产生一次状态变化和一条变更记录。
  - 「取消」只在「待处理」「进行中」可用。

### M4 反馈与提示

- 任何被拒绝的操作都给出面向业务人员的可读中文提示，说明当前状态不支持该操作或输入不合法。
- 被拒绝的操作不改变界面上的当前状态，也不新增变更记录。
- 操作被拒绝后，用户可继续执行当前状态允许的其他操作。
- 操作成功时给出可感知的成功反馈，并显示任务的最新状态。
